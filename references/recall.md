# 回读、整理与复盘

优先查询用户已有的平台存储，下文多表与 library 示例用于云端方案；其他平台按实际过滤和分页契约回读。只有用户已选可选本地扩展才按 [local-runtime.md](local-runtime.md) 使用 list/get；不要为查询旧记录初始化新库。任何接口返回的原文与内部字段都不直接整份贴给用户。

## 查找

优先带条件、分页读取，避免默认整表导出。先检查当前表；旧表与归档表的范围以云端配置为准，不能说“没有”却只查当前页或当年表。

| 用户问 | 查询方式 |
|---|---|
| 关于某人 | 按相关人筛，已知别称分别查；`contains` 会命中同字不同人，结果须核对 |
| 上次那个想法 | 线索/关键词定位，必要时以受限范围的语义检索补充 |
| 本周工作待办 | 领域、状态、类型与用户时区日期范围组合过滤 |
| 最该先做哪个 | 未完成待办/计划按优先级、到期排序，通常返回前三条；空优先级不冒充高 |
| 一个线索如何演变 | 按线索查询所有记录，记录时间升序，保留各记录不同状态 |
| 我当时怎么说的 | 逐字给原文；空值直说未保存原话，不用内容冒充 |

接口层级、过滤器和分页参数以适配器帮助为准，不把文档示例当作已验证的服务响应。
日期检索遵循 [时间规范](timestamps.md)：用户时区首日零点包含、末日次日零点不包含，兼容旧日期值，不用字符串等值/前缀替代。条件组合后再分页；本地用 list --date 或 --from-date/--to-date，--timezone 仅覆盖本次查询。
排序枚举若采用 library 约定，使用 `ascending/descending`，不要自行缩写。

## 整理与档案

按用户给定时间和主题整理，默认在对话中给结果；要求保存成文档时写入已配置的记兜目录并回读访问链接。
主体使用内容摘要，待办列未完成项，说明想法的重复与演进。用户需要追溯档案原话时，在文末放对应原文附录；普通周报不默认倾倒原文。
记录多于五条可以建议建立档案，不因条数达到阈值就自行创建文档。整理不改变原记录状态。

## 复盘和回顾

完成数按记录的状态与完成于统计，不把逾期或仅查看算已完成。按记录粒度报告，避免把同一主题的多条碎片说成多个独立项目。
完成于只有日期时，按用户时区取记录时间的日历日期后计算日历天差；不代表精确到小时的历时或实际工作耗时。不得给完成日期补零点后声称算出了精确耗时。
随机回顾可抽 3–5 条跨时间的未完成想法/疑问；给简述，不替用户宣布旧观点已经失效。

## 习惯打卡

循环模板持续存在，每次打卡新增记录并复用线索。系统生成的“打卡”摘要不能伪造为用户原文；用户明确打卡时保存其实际说法。
按用户时区的不同日期去重计数，先按 capture.md 核对有效完成回执，排除已撤销/voided 和只跳过的记录。同一天多条不算连续多天；连续天数以今天/昨天最近一次打卡向前数，到缺失日停止。
补打卡注明实际发生日期和补记日期；无明确习惯频率时不凭空计算连续率。

## 数据量变大

先分页、筛选与确认接口性能，不把固定行数当平台容量承诺。
分表、跨表归档和迁移属于 [upgrade.md](upgrade.md) 的维护操作，按用户需求进行；普通查询不自动跨年建表或搬数据。
