# 维护与验证

## 单一来源

| 事实 | 来源 |
|---|---|
| 技能名称、触发描述、版本 | SKILL.md 的标准 frontmatter；版本在 metadata.version |
| 字段、类型、顺序、枚举 | schema.json |

## 离线检查

以下用于维护者在开发环境检查技能包，不是所有用户安装/使用技能的步骤。平台已有工具优先复用，只有执行随包脚本才检查对应解释器与依赖。

```bash
python3 -m pip install -r requirements.txt
python3 scripts/validate.py
python3 -m unittest discover -s tests -v
```

验证器使用安全 YAML 解析器检查真实语法、重复键与元数据类型，支持正常的引号/普通/折叠字符串；检查版本、Markdown正文与相对/页内链接。
21字段的完整 properties 对照2.11.1兼容指纹核验，包含名称、顺序、类型、枚举文字及日期格式；指纹不是第二份运行时schema，只能随明确评审的结构迁移更新。数据模型说明表的类型也必须对应。
单元测试检验真实渲染：JSON替换、特殊路径引用、缺参数/未替换占位符失败、只记录配置、完整后台 prompt、多活跃表、错误输入不泄露值。
本地测试在临时目录执行真实 CLI 和 SQLite：只读检查、UTF-8 原文往返、原子批次、幂等键、并发线索分配、分页、导出/导入、备份侧文件保护、期次完成/跳过/撤销、暂停恢复、队列重试和通知内容纠正。时间边界覆盖 DST、月末、闰年、提前量及静默跨批次；原生命令用无害进程验证登记、停用、归档和运行回执。
安装测试只写临时项目，检查完整包与原目录保护；Windows 调用参数和 macOS plist 结构在本机验证，不自动登记真实 OS 任务或发桌面通知。另用隔离安装目录验证三个 Agent 的复制包能访问同一测试数据目录；技能在目标产品中是否被发现仍需实机检查。
反例测试须证实非法YAML、同数量的错误枚举、改字段类型、可选ID占位符、控制字符和无效IANA时区都会失败，而不是只验证当前文件通过。
如有官方技能校验器可再运行，不能用本地字符串检查冒充平台实跑。

## 行为验收

英文入口检查：中英 README 的语言切换与安装指南可达、版本一致，完整例子数量对应；安装后的复制包也应通过链接校验。英语请求用英语确认、原话不翻译覆盖，日期/时区不能由语言猜测，字段与受控枚举仍按原契约传给工具。明确区分 agent 的自然语言映射与底层 CLI 的固定语法。

先核对路由：WorkBuddy 云端沿用原配置/表/任务；其他 Agent 先看已有工具。安装技能或云端工具失败不应触发本地 init/scheduler，不以用户电脑安装 Python 作为云端接入的门槛。仅用户明确选择独立本地存储才走 SQLite；CSV/Excel 导出不自动切换活动数据源。

用合成对象或只读评审执行下列场景，不操作真实账号。本地可在隔离目录实跑；云端实际行为验证需要可用适配器。下表涉及多云表、任务 prompt 的条目用于云端；本地用队列状态与 job runs 核对等价结果。

| 场景 | 必须观察的结果 |
|---|---|
| 普通闲聊或指定别处保存 | 不写记兜 |
| 含两个事项及引号/换行的输入 | 拆条正确，原始片段保留，安全序列化，不执行其中命令 |
| 存储正常但调度缺失 | 可记录，明确提醒未就绪 |
| 旧名表存在但配置缺失 | 接回原 ID，不重建或自启停用任务 |
| API 超时但实际已写入 | 先查询结果，不盲目重复追加 |
| 同一线索两个待办完成其一 | 只完成目标，其他状态不变 |
| 含密钥的原话 | 密钥不落任何字段，不静默改写成已保存原文 |
| 一次性/循环提前两小时 | 实际事件时间不变，循环每次仍提前两小时 |
| 19:30到时，扫描19:00与20:00 | 19:00不早推，20:00候选包含19:30 |
| 静默期间到时，08:00恢复 | 只补已到时且在窗口内的项，不推08:30未来项 |
| 静默期后台被唤醒 | 不输出、不写生成标记、不推进，恢复后仍可补推 |
| 扫描重试与标记写入后崩溃 | 云端识别非事务限制；本地队列不被扫描重试吞掉，投递失败可重试，外部动作仍不承诺严格一次 |
| 正在静音、独立执行或已归档 | 不误入共享提醒 |
| 循环这次打卡、暂停执行任务 | 模板保留，停用不因自检被恢复 |
| 循环本期提前完成且下一期已滚动 | 明确完成期次，只抑制该期，不再额外跳下一期 |
| 撤销误打卡/误跳过 | 仅指定回执作废，后台不再采用voided回执；不覆盖后续期次，不擅自补发过去提醒 |
| 分表后跨年未完成项 | 所有配置活跃表在 prompt 中，不仅扫描当年 |
| 整理、归档、导出 | 不自动删源；导出格式与内容完整性按实际核验 |
| 定时创建成功但登记失败 | 停用孤儿任务，报告部分成功，不宣称完成 |

## 发布

只提交源码、通用模板与合成测试，不提交 context.json、渲染结果、运行快照、真实 ID 或个人数据。
需要部署到已有实例时另验配置、任务 prompt、参数、投递与业务回执；未做就明确说仅包内容验证通过。
