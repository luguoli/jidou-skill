# 定位与首次使用

本地没有文件、查询报错、没有调度服务，都不能证明用户尚未使用记兜。日常记录不运行初始化脚本。

## 三查一问

| 顺序 | 查找 | 命中后 |
|---|---|---|
| 1 | 云端「记兜·配置」及兼容旧名，验证配置的表 ID | 继续使用原 ID；任务状态独立检查 |
| 2 | 已选空间内的「记兜」表及兼容旧名，必要时分页和下钻 | 核对 schema 与归属；确认目标后沿用，获准维护配置时补配置 |
| 3 | 同一账号、用户授权范围内按标题/已知主题找其他位置 | 唯一匹配才接回；多个候选让用户选，不自动合并 |
| 问 | 查找均正常完成但没有可用对象 | 问第一次使用、已有记录要找回，还是先不建 |

各查都考虑 [旧名映射](upgrade.md#记兜命名升级)。网络错误、分页未完或无权限时标记“无法确认”，不进入“确定不存在”。不跨账号扩大搜索范围。

可问：「还没找到可用的记兜。要新建一个收集箱、继续找原来的记录，还是这次先只整理在聊天里？」
用户已明确要求安装并创建收集箱时，沿用已有授权，不重复问同一件事。

## 能力与选择

- 只记录：只准备存储与配置，不因缺调度而阻止保存。
- 需要提醒：说明共享扫描精度与依赖；用户同意开通后才创建任务。
- 先不建：不创建目录、空表、配置或任务，清楚说明候选内容尚未持久保存。
- 以前有：继续核查账号、空间、旧名与配置，不靠新建来解决“找不到”。

首次配置就绪后简短展示已可用的能力和三类试说句，完整清单在 [onboarding.md](onboarding.md)。未就绪的能力标明条件。

## 重入、修复与停用

已存在的表、目录和配置保持原 ID。缺少可选任务不触发整套初始化；配置引用失效时保留恢复线索。
找到停用任务就保持停用并告知，不能把自检变成自动启用；只有用户要求恢复时才启用。
读取不触发补字段、移动表、重置、安装依赖或自动升级。用户已授权本次修复时，在授权范围内补缺后回读。

## 重置

只有用户明确要求重置才先备份、核对目标及关联任务。旧数据保留，不自动删除。
若将旧表改名归档，使用 `记兜-归档-YYYYMMDD`，更新配置、所有活跃表列表和关联任务指令，再回读验证。不能把删表和重建当日常自愈。
