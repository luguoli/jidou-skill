# 平台适配边界

记兜的记录模型可移植；本仓库中的 library/scheduler 命令是当前适配器示例。换路径只能解决文件位置，不能替代 API、鉴权、响应和时区适配。

## 适配顺序

1. 存储：21字段的名称/顺序/类型/枚举，带时区日期精度，分页与过滤，写入回读、部分成功、幂等键和空值更新语义。
2. 身份与配置：目标账号/空间、对象归属、云端配置定位、跨设备可读性；不能依赖对话沙箱的本地配置。
3. 调度与通知：cron 段数/星期编号、时区、启停、重试、一次性运行、配额、投递能力；实际行为逐项验证。
4. 后台执行：工具可用路径、网络、凭据引用、隔离边界、产物持久化、业务回执。
5. 日期：当前用户时区、IANA时区数据库、农历换算库或等价服务。不能假设安装环境自带 lunardate。

能力不足时减少可用操作，不删 schema 里的枚举或字段。能记录但不能提醒时，清楚说明尚未启用。

## 加载器

SKILL.md 使用标准 name/description/license/metadata，适用于接受该格式的技能加载器。
旧版顶层 slug/displayName/display_name/display_name_en/version/summary/description_zh/description_en/category/triggers 不再作为必需协议；中文、英文名称与版本见 metadata。
原平台若必须使用这些字段，可在平台专用适配配置里映射，保留标准入口，不向未验证加载器承诺兼容。
当前技能名为 jidou，仓库克隆目录可以叫 jidou-skill；安装时放入加载器实际查找的 jidou 目录。

## 后台模板

当前 reminder 渲染器输出 POSIX shell 的 library 命令，SKILLS_DIR 必须是后台真实的绝对 POSIX 路径；在 Windows 本机渲染、目标后台为 Linux 时也使用后台路径。
Windows 后台或其他调用约定需提供并验证对应的原生适配模板，不能把 Windows 盘符路径填进 shell 模板就宣称可运行。schema/config 渲染本身不依赖目标 shell。

## 迁移验收

先用合成数据测试含引号/多行原文、中文、同线索不同状态、日期偏移、分页、循环和部分失败，再迁移真实记录。
任务独立运行时必须能访问新的实际工具路径、全部活跃表与凭据；导出器返回格式和调度器“启动过/完成/送达”的区别不可省略。
正文示例是操作方法，不是目标环境已验证事实；未连接平台时只报告离线检查结果。
