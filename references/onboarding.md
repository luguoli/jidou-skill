# 可以怎么用记兜

首次就绪时先说明已经可用的能力，给下列三句示例；用户要求完整介绍时再展示后面的清单。没有调度或后台执行能力时明确标注尚未开通。

先使用用户已有的存储与平台工具；WorkBuddy 云端继续保存到原 library 数据表，依赖在云端检查，不能先要求用户电脑安装 Python。安装本技能本身不等于创建本地库或开启后台。
用户明确选择可选本地扩展时，才需要执行本地 Python；同一用户和数据目录可供多个 Agent 共享，另一台电脑需明确迁移或云端配置。本机后台无需保持聊天打开，但电脑休眠/注销仍会延迟；远程沙箱不会自动连接用户电脑。

- 记录：「记一下：周报能不能从聊天记录自动生成。」
- 提醒：「每月5号交房租，提前两天提醒。」
- 执行：「每周一早上8点，整理上周记录，生成周报。」

## 完整能力清单

| 能力 | 示例 |
|---|---|
| 记想法 | 记一下，周报能不能自动生成 |
| 存参考 | 这个链接留着，讲缓存穿透的 |
| 留摘录 | 把这句话原样记下来 |
| 记疑问 | 为什么月底对账总是对不上 |
| 留决策 | 定了，以后用模板A，并记下原因 |
| 记计划 | 三个月内把内容号做起来 |
| 记待办 | 下周把合同发给老张 |
| 无日期待办 | 报税这事先记着，没定什么时候 |
| 记事件 | 11月20号早上9点体检 |
| 固定提前量 | 提前一天提醒 |
| 自定义提前量 | 提前两小时提醒，事件时间不变 |
| 循环提醒 | 每周一、周四晚上8点 |
| 农历提醒 | 每年农历三月二十八，妈妈生日 |
| 静音 | 这周先别提醒 |
| 单次或长期改期 | 这次改到明天，以后仍按原计划 |
| 完成或结束系列 | 这次做完了 / 以后不需要这个循环了 |
| 纠错 | 是下周三，不是这周三 |
| 追加线索 | 上次那个周报，又想到一点 |
| 回读 | 上个月我记了什么定价的想法 |
| 整理 | 把这周的碎片理一理 |
| 复盘 | 这个月真正完成了哪些 |
| 定时脚本 | 每天7点执行已配置的脚本 |
| 定时接口 | 每小时看接口，有变化再告诉我 |
| 定时技能 | 每周一整理上周记录 |
| 多步执行 | 拉数据、生成日报、将结果给我 |
| 自动分领域 | 空调清洗归生活，缴费归财务 |
| 按领域查看 | 工作上还有什么没做完 |
| 优先级 | 这件事周四截止，会影响别人 |
| 随机回顾 | 随便抽几条旧想法给我看看 |
| 习惯打卡 | 今天跑步打卡，看看连续几天 |
| 找回原话 | 我当时到底是怎么说的 |

类型无需记术语，按你平时的说法表达即可；判断错了可以直接纠正。记录原话与一句话摘要分别保存，普通提醒和摘要不展示原话。

## 提醒和执行

| | 提醒 | 执行 |
|---|---|---|
| 做什么 | 到时告诉你 | 到时调用已配置的工具 |
| 运行方式 | 共用周期扫描 | 每个需求有独立任务 |
| 时间边界 | 云端默认每小时扫描，本地默认每分钟唤醒；扫描周期、休眠和排队会导致延迟 | 按调度器触发，不保证准时开始或完成 |
| 结果 | 提醒正文；排队、通道接受与用户读到分别核对 | 业务产物与成功/失败/未知回执 |

默认用户时区为 Asia/Shanghai，可按实际偏好配置。默认22点到次日8点不推送；最近一天内的到时提醒可在恢复后补发，不保证补回长时间停机的历史提醒。
记录、提醒、执行可分别启用。用户暂停的任务保持暂停；“记一下”不会替你创建一堆后台任务。

## 边界

普通记录不做数值统计或医学/财务判断；文件本体走文件存储，表内存链接。
密码、密钥、证件号、银行卡号不要发进记兜，原文也不存这些秘密。
后台不一定能访问你电脑上的文件或当前聊天的连接。独立任务要有自己的可用工具、数据源和凭据配置。
