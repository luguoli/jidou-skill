# 升级、备份与数据维护

## 维护范围

用户要求修改本技能可更新仓库文件；不因此自动改运行中的表、配置、提醒任务或安装依赖。
后台 prompt 是创建时的快照，改仓库不会自动改变已部署任务。涉及实例行为的升级，说明变更并沿用用户对该实例的授权；读记录时不自动升级。
保持字段顺序与已有 ID，只在确有需求且获授权时追加字段/选项。状态与时间语义变化需要说明迁移影响，不能把版本号变化当作数据已迁移。

## 从 2.13.1 升级到 2.13.2

新增完整英文 README、英文安装指南与 agent 的语言/时区规则；英文触发词和同语言回复更明确。原话按原语言保存，英文类别与循环需求由 agent 映射到已有字段和规则，不改变21字段、枚举或数据库版本，也不自动翻译历史记录。
随包安装器现在同时复制 README.en.md，校验器检查中英文 README 的版本和引用。英文自然语言入口不代表底层 CLI 新增了英文字段别名或任意英文循环解析；这些转换由 agent 完成。独立云端任务需要输出语言时，在获准创建/更新任务时写进其指令，不自动修改现役任务。

## 从 2.13.0 升级到 2.13.1

修正入口与安装说明：优先使用平台已有存储和调度，WorkBuddy 云端保持原 library/automation-task-manager 流程。平台导入/手动复制不需要 Python，脚本依赖在实际执行环境检查；SQLite、本机调度与 Python 复制工具均为可选扩展。
此次只改说明、版本和 README 校验条件，不修改云端模板、21字段、运行代码或已有数据。不删除已明确启用的本地数据库/任务；已有本地用户可继续使用，不能把文档优先级调整当作停用或迁移授权。未选本地扩展的云端用户无需初始化 SQLite。

## 从 2.12.x 升级到 2.13.0

- 保持标准 SKILL.md 和原21业务字段；已有云端实例沿用原 ID、数据和任务，安装新包不自动切换本地，也不更新现役云端 prompt。
- 新增本地后端是可选方案，需明确选择后 init。SQLite 内部数据库版本为1，元数据/队列/运行表不是新增业务字段。不要用云端表 ID 代替本地库身份。
- 本地记录导出/导入保留原文、时间和期次关系；不恢复待发队列、可执行 jobs 或 OS 注册，防止迁移后误执行。完整状态备份使用 backup API；恢复前停用指向该库的 worker，保留原库与侧文件，再核验目标和状态，不能在运行中覆盖主库。
- 本地与云端没有自动双写/同步。云端导出先按实际格式核验并映射为 jidou 导入格式，不能把任意 library 响应直接交给 import。先小样本验证，迁移完成再明确切换后端。
- 安装器只覆盖带本包托管标记且无额外用户文件的目录，保留旧包备份；未托管旧安装先备份并人工核对位置。后台注册固定解释器、脚本和数据路径；移动安装后须核对原注册，不能叠加重复任务。
- 升级先检查 requirements.txt；新增 lunardate 用于农历，Windows 保留 tzdata。用户已有的停用状态不恢复；无目标系统实测时只报告包与配置检查结果。

## 记兜命名升级

旧名称仅用于接回已有对象，不用于新建。

| 对象 | 旧名 | 当前名 |
|---|---|---|
| 技能/安装目录 | `quicksave` | `jidou` |
| 展示名 | 随手记 / Quick Save | 记兜 / jidou |
| 表和目录 | `速记箱` | `记兜` |
| 配置 | `速记箱·配置` | `记兜·配置` |
| 提醒任务 | `速记提醒` | `记兜提醒` |

按 [first-run.md](first-run.md) 每一步同时考虑新旧名称、分页和位置变化。有效配置 ID 优先；同名或新旧对象同时存在时核对归属和用户目标，不合并覆盖。
要求实际改名时原地更名保留 ID，更新配置和任务指令并回读；查到旧名不自动授权改名、搬目录、启用任务或新建替代品。

## 从 2.11.x 升级

1. **技能包。** 顶层改为标准 name/description/license/metadata；版本等展示信息移到 metadata。旧平台若依赖专用顶层字段，按 [portability.md](portability.md) 映射，不能宣称所有加载器兼容。
2. **数据结构。** schema 的 21 个字段和枚举完全不变。历史原文为空就保持为空；不从内容伪造原文。
3. **提醒方案。** 旧文本循环和旧枚举仍可读；新自定义提前量写结构化重复参数，真实到期不再改成提醒日期。旧方案已把真实时间挪进内容的记录不能自动推回，先呈现候选让用户确认原事件时间。
4. **生成标记。** 新扫描使用上次结果生成标记，绝不声称等于送达；执行类行继续使用执行回执。迁移时明确 reminder_start_at，避免把旧的已提醒事项再当新通知；若要补历史未送达项由用户决定。
5. **配置。** 沿用旧 ID，补 timezone、active_database_ids、reminder_status、reminder_start_at，未启用能力保持禁用。存在跨年未完成项时把其所在表加入活跃列表。
6. **部署。** 用户要求同步实例时，先备份现役配置与 prompt，渲染新 prompt，按原任务 ID 更新。保留用户选择的启停、时区与频率，默认重试差异明确核对；用户已暂停的任务不自动恢复。
7. **验收。** 回读表结构、任务参数与完整 prompt，确认所有活跃表 ID、绝对工具路径及启用时间正确。无存储/调度会话时只能验证包内容，不能报告实例已升级。

## 备份和回退

### 从 2.12.0 升级到 2.12.1

入口格式不变，仍是 YAML frontmatter 加 Markdown 正文；保持原21字段及枚举，无需数据结构迁移。
渲染与校验脚本现在使用 PyYAML 真正解析元数据，并使用 IANA 时区数据核验时区；先检查 requirements.txt 的依赖。已有合法配置不需要重建，未替换占位符和错误时区会被拒绝。
新回执可记录 completed/skipped/voided；旧2.12.0的无status完成回执仅在其记录仍为已完成时有效。需要撤销旧误打卡/跳过时按 capture.md 核对目标，不能批量改写历史记录。
后台模板的撤销回执规则仍需在用户要求部署时同步，改仓库不代表现役任务已更新。

先保存 Git 提交和待改文件快照；运行时备份另包含云端配置、schema、任务 prompt 与参数、实际记录导出。
按导出器实际格式保存。返回 JSON 就命名 `.json`，不能仅把输出重定向到 `.csv` 冒充 CSV；多行引文的 CSV 不能用物理行数当记录数。
验证完整分页、逻辑记录数、所有字段（含原文）、时间与选项；恢复流程需按字段名映射，不沿用新服务不接受的字段 ID。
记录导出含个人内容，不进 Git；仓库排除 archive/、本地配置、导出文件和 context.json。快照只新增，不改写旧版。
回滚按实际改动恢复文件、配置与任务参数；已产生的外部动作不能靠回滚文档撤销。没有改云端时不编造 schema/data 快照。

## 分表与归档

先优化分页和过滤。只有用户需要或实际性能表明确有必要时才建议分表，不以3000/10000行作为未经验证的容量边界。
分表沿用同结构，登记当前主表与所有仍有未完成项的活跃表，同步提醒 prompt；读旧记录时仍可检索归档表。
归档首先是状态变更。跨表迁移须验证完整字段、记录数、线索、时间、原文与目标；核对数量不等于证明内容完整。
默认保留源记录。只有用户明确要求删除源数据且备份/目标验证完成后，才在该授权范围内删除；不能把“整理/升级”当删除许可。
不做无恢复计划的自动双写。跨平台先小样本验证、完整迁移、核对，再切换，保留可回退的原数据源。
