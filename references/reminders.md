# 提醒管理

## 时间含义

「到期」保留真实发生/截止时间；「下次触发」保存当前待提醒的实际事件时刻。两者都不通过减去提前量伪装成提醒时间。
提醒时刻 = 当前事件时刻 − 提前分钟数。以用户时区计算，写 ISO 值时保留偏移。

| 请求 | 处理 |
|---|---|
| 没有时间的待办 | 保存，不提醒 |
| 提醒我，但没说时间 | 先保存需求，再问什么时候；不宣称已设提醒 |
| 只有明确日期 | 可用 09:00，回复中明确该默认值；不替用户推断“下午” |
| 下午、下班前等模糊时段 | 结合已知偏好提出具体时刻并说明；会产生实际动作且无法合理确定时问一句 |
| 已经过去的时间 | 核对是否补记、立刻提醒或下次发生，不自动跨年/跨日 |

默认设置来自 [defaults.json](defaults.json)：每小时扫描，用户时区默认 Asia/Shanghai，夜间静默。扫描只在目标时刻已到后推送，正常可晚一个扫描周期加排队时间，不能承诺分钟级准点或“最多只差几分钟”。

## 循环和提前量

普通规则可继续使用旧文本，例如 `每天 08:00`、`每周一、周四 20:00`、`每月5号 10:00`、`每月最后一天 18:00`、`每年3月28日 09:00`、`每年农历三月二十八 09:00`。
工作日默认周一至周五，不含节假日调休；用户要求真正工作日时需可验证的地区日历。每 N 天/隔周必须持久保存锚点，不能每次从“今天”重算。
无效日期明确采用跳过规则：每月31日跳过无31日的月份，2月29日跳过非闰年；用户要月底就用月底规则。农历闰月须明确，库不可用时不猜公历日期。

标准提前量直接使用 schema 的提醒枚举。自定义提前量不新增字段，也不改真实日期：在「重复」字段写结构化参数，提醒枚举填准时。

```json
{"rule":"每月5号 10:00","lead_minutes":2880,"timezone":"Asia/Shanghai"}
```

这表示每月5日10:00发生、提前两天提醒。一次性自定义提前量用 `rule:null`，不是“重复非空就是循环”。

```json
{"rule":null,"lead_minutes":120,"timezone":"Asia/Shanghai"}
```

隔周或每 N 天增加 `anchor`（ISO 日期/带偏移时间）；只改这一次提醒可增加 `override_reminder_at`（带偏移 ISO 时刻）。结构化规则只在本次需要时写，不批量重写旧记录。
存在结构化提前量时只减一次，不再叠加枚举提前量。数字须非负；规则或时区无法解析时保留需求、报告尚未排期，不胡猜。
有夏令时的地区，遇到不存在或重复的本地时刻须核对实际偏移/用户选择，不默默挪动时刻。任务时区须通过 IANA 数据校验，后台仍需验证同一时区可用。

## 改期、静音、完成

| 用户意图 | 修改 |
|---|---|
| 一次性事件本身改期 | 到期与下次触发一起改，并清除旧的生成标记/一次性提醒覆盖值 |
| 只换这次提醒时间，事件时间没变 | 保留事件时间，在规则中写 override_reminder_at |
| 循环事件这一次改期 | 下次触发改成本期实际时刻；到期保留系列锚点，重复规则不变 |
| 以后永久换到周三 | 改重复规则、必要时更新锚点，再重算下次触发 |
| 这期跳过 | 明确期次，先留一条归档的 occurrence/skipped 子回执（含模板database_id/record_id和event_at），再更新模板同一期标记并推进；已到更晚一期则不多跳 |
| 一段时间别提醒 | 写静音至；静音期间过去的提醒不在恢复时补轰炸 |
| 这次做完了 | 按 capture.md 的本期完成流程，抑制明确期次的提醒并保留后续循环 |
| 以后不用提醒/整个任务不做了 | 明确关闭该提醒或归档模板；关联执行任务另行停用 |
| 刚才打卡/跳过弄错了 | 按 capture.md 撤销指定回执，不清掉后来其他期次的状态 |

静音截止使用明确日期时刻：这周=本周日结束；今天是周日仍是今天，不擅自延长一周。月底前=本月结束；不知道何时出差回来就问日期。
改时间后旧通知不能撤回；新的生成标记按新提醒时刻区分，故同记录可以按新时间提醒一次。

## 扫描与重复控制

运行算法只在 [reminder-rules.md](reminder-rules.md)，由 `scripts/render.py` 嵌入后台 prompt；后台不依赖本地技能文档。
共享扫描排除独立执行记录，完整读取所有活跃表及分页。默认只补最近一天内、启用后尚未生成的到时提醒，夜间到08点后补推；更久的逾期项供用户主动回读。
「上次结果」保存提醒生成标记，说明已生成而非已投递。数据写入、任务输出和通知投递没有共同事务；无法保证恰好一次或绝不漏送。默认共享扫描关闭自动重试以减少重复；需要强保障时须适配支持投递回执和幂等的服务。

## 初始化与健康

创建和更新按 [bootstrap.md](bootstrap.md) 使用实际能力与 defaults 参数。配置 ID 优先，旧名称兼容查重；停用任务保持停用。
只验证本次操作所需能力；不要每次普通记录都全空间扫描、改 cron 或新建任务。用户没有要求提醒时不创建调度资源。
修改已发布模板不会自动更新既有云端任务；升级时需明确同步 prompt，并验证它指向的全部活跃表。
