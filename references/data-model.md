# 数据约定

自然语言可以使用中文、英文或混合语言；字段名/受控枚举继续沿用现有结构，由 agent 按 [语言映射](language.md) 转换工具参数、翻译展示标签。原文不翻译覆盖，不新建另一套英文数据表来处理英文输入。

## 存储形式

WorkBuddy 原方案通过 library 的 database 接口读写云端「记兜」表，用表 ID、记录 ID 和字段结构定位；表格界面不等于本地 Excel .xlsx 文件。导出的 CSV/Excel 是副本或备份，不自动成为日常记录来源；实际导出格式由工具返回决定，不能把 JSON 改扩展名冒充 Excel。
可选 SQLite 是用户明确选择的另一种本地存储：保存记录与原文，也管理提醒队列和执行回执，不自动缓存、同步或替代原云端表。未选本地方案就不创建 jidou.sqlite3。
用户明确指定某个 Excel 工作簿时沿用该目标及可用表格工具，遵守同样的原文与字段语义；本包没有新增通用 Excel 适配器，不自动把已有文件迁移到 SQLite。未连接实际实例时不能仅凭代码声称用户的数据当前存放在哪里。

## 结构与兼容

可选本地 SQLite 保留下表同名21业务字段并按本 schema 的枚举和日期语义校验，内部以文本存储；id/创建更新时间、幂等键、期次关系、通知队列与任务运行另行管理，不是新增业务字段。云端选项 ID 只用于原服务，不拿它冒充本地记录 ID。

[schema.json](schema.json) 是建表结构的唯一来源；渲染时只替换空间和父目录 ID。现有 21 个字段与顺序保持不变，第一列是「内容」，没有隐式 `名称/title` 列。枚举只能使用结构中已有文字；更新选项时保留已有 ID。

| 字段 | 类型 | 填写规则 |
|---|---|---|
| 内容 | text | 整理后的一句话，开头能认出是什么事，不改变用户观点 |
| 类型 | select | 按下方分类判断，取值以 schema 为准 |
| 标签 | text | 2–4 个主题词，以 `、` 分隔；同主题复用写法 |
| 线索 | text | 同一主题共用稳定编号，格式 `QYYYYMMDD-NN` |
| 记录时间 | date | 用户时区中的记录日期 |
| 状态 | select | 新记录通常待看；推进中用进行中；完成与归档见 capture.md |
| 到期 | date | 用户实际截止或发生时刻，不为实现提前提醒而改成另一时间 |
| 提醒 | select | 无时间或用户说不提醒时用不提醒；已启用提醒的收集箱中，带明确时间的待办/事件默认准时，显式提前量优先 |
| 重复 | text | 普通循环规则；复杂规则与自定义提前量见 reminders.md |
| 下次触发 | date | 下一次实际事件时刻；一次性默认等于到期，可为空 |
| 静音至 | date | 在此时刻前不推送；不代表删除或完成 |
| 完成于 | date | 完成该记录时填写；日期代表记录级完成，不是后台启动时间 |
| 执行 | select | 空或仅提醒走共享扫描；其他取值走独立执行任务 |
| 执行内容 | text | 不含秘密的命令、方法/URL、技能或步骤描述 |
| 任务ID | text | 独立执行任务返回的实际 ID；不猜、不用示例 ID |
| 上次结果 | text | 执行回执、提醒生成标记，或循环期次的完成/跳过回执；以 kind 区分，不把任意同线索记录当本期完成 |
| 领域 | select | 每条一个领域；按用途选择，不确定用其他 |
| 优先级 | select | 仅需排先后的待办/计划填写；无必要留空 |
| 相关人 | text | 人名/称呼；多人以 `、` 分隔，不擅自推断是同一个人 |
| 来源 | text | 用户提供的链接、书名页码、场合；未知留空，URL 去掉凭据 |
| 原文 | text | 用户实际输入的原始片段；系统回执可空；禁止含秘密 |

ISO 时间必须带偏移或时区，例如 `2026-11-20T18:30:00+08:00`。API 转成 UTC 后须比较同一时刻，不以界面仅显示日期就判断时分丢失。跨平台是否保存时间精度需实测。

## 分类

| 类型 | 用途与判断 |
|---|---|
| 想法 | 尚未决定实施的主意或假设 |
| 待办 | 需要人完成的动作，含缴费、提交、联系等 |
| 事件 | 发生的时间点，如生日、纪念日、预约时间 |
| 参考 | 外部资料、链接、供以后查找的信息 |
| 决策 | 已作出的选择及理由；通常记录为已完成并填完成于 |
| 摘录 | 需要保留原段落的材料或原始观测；摘要进内容，原话/数值进原文 |
| 疑问 | 待解答的问题 |
| 计划 | 跨步骤的目标；子待办可与其共用线索 |
| 复盘 | 事后的回顾与结论 |
| 定时 | 已明确要求系统按时执行的动作 |

一个句子可拆出不同类型，例如会议原话一条摘录，明确的跟进项另记待办。不要给十类之外再造枚举。
领域按实际目的区分：职业交付→工作，家庭日常→生活，自我学习→学习，身体就医运动→健康，账单收支→财务，其余→其他。用户指定时优先使用用户判断。

## 线索与状态

新线索取当日已用最大序号 +1，序号超过 99 时继续递增，不截断。并发写入需由适配器串行或唯一约束分配，不能宣称“读最大值”本身保证唯一。回读检查碰撞，发生碰撞先停下核对，不改掉已被引用的旧编号。
同一线索是主题关联，不是共享状态。补充通常新增记录；纠错更新目标；一个计划下完成一个待办不影响其他待办或计划状态。

健康和财务数据只作用户请求的记录，不据此推断诊断或投资建议。附件本体由用户选定的文件存储处理，表内只保存可访问的来源链接。
