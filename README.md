# 记兜 · jidou

聊天里的个人收集箱。把随口说的想法、待办和琐事接住，保留原话、自动归类，需要时找回、提醒或执行。

> 「记一下：周报能不能从聊天记录自动生成。」
> 「每月5号交房租，提前两天提醒。」
> 「关于老张的那些事，我都记哪了？」

## 能做什么

| 能力 | 行为 |
|---|---|
| 记录 | 一件事一行，摘要与原话分开；按类型、领域、标签、相关人归类 |
| 线索 | 同一主题多次补充，共用稳定编号，回看演进 |
| 回读和整理 | 按人、日期、主题、状态找回；整理、复盘、习惯打卡 |
| 提醒 | 一次性、循环、自定义提前量、静音和单次改期；保留真实事件时间 |
| 定时执行 | 依赖后台能力，按请求跑脚本、调接口、触发技能或多步组合；回写结果 |

完整示例见 [使用说明](references/onboarding.md)。普通闲聊不自动保存，指定其他保存位置时尊重该位置。

## 安装与依赖

将仓库放入所用加载器的技能目录，技能目录名使用 `jidou`。当前适配器常见安装方式：

```bash
git clone https://github.com/luguoli/jidou-skill.git ~/.codebuddy/skills/jidou
```

**克隆不等于服务已配置。** 当前运行示例依赖未随仓库打包的 `library` 存储能力，以及可选的 `automation-task-manager` 调度/后台能力。支持标准 SKILL.md 的加载器可读取入口，但运行接口仍需[适配和验证](references/portability.md)。
先接回已有数据；只有用户要求初始化才建表。没有调度时仍可记录，但不能承诺已设置提醒。已有安装升级先看 [迁移说明](references/upgrade.md)。

## 数据与时间

保留原有21字段及顺序，机器定义在 [schema.json](references/schema.json)，含义在 [数据约定](references/data-model.md)。原文逐字保存，普通摘要和提醒使用整理后的内容；密码、密钥、证件号、银行卡号不进入任何字段。
默认共享提醒按小时扫描，22:00–08:00静默，可配置时区；正常提醒可能晚一个扫描周期加排队时间。生成、持久标记和通知投递不在同一事务中，不能保证严格一次或绝不漏送。分钟级需求须另配任务并核验实际调度能力。
实例 ID 只进入云端配置和已授权任务，不写回仓库；记录、提醒、执行分别按实际就绪状态报告。

## 文件

```text
jidou/
├── SKILL.md                 标准元数据与精简入口
├── references/              按任务加载的流程、schema、默认值和模板
├── scripts/render.py        安全渲染初始化/配置/后台提示，不调用云端
├── scripts/validate.py      包的一致性校验
└── tests/                   合成数据的离线测试
```

运行时存储、查询和任务操作仍通过实际平台适配器。仓库脚本只负责渲染与校验，使用 Python 标准库，不携带平台 API 副本。

## 维护

```bash
python scripts/validate.py
python -m unittest discover -s tests -v
```

[维护检查](references/consistency.md) 说明行为验收与部署检查。离线测试不代表真实平台已建表、提醒已投递或后台任务已成功执行。
