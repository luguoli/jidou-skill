# 随手记 · Quick Save

把聊天里随手扔过来的一句话接住、归类、存进一张表，需要的时候能翻回来。

> 「记一下，下周三之前把周报模板改完」
> 「又想到一个，那个周报能不能自动从聊天记录里长出来」
> 「关于老张那些事我都记哪了？」

这不是待办清单，是**收集箱**。想法、待办、事件、参考链接、临时决策、摘抄，都往同一个地方落，之后再分流。

---

## 它到底做什么

| 动作 | 具体行为 |
|---|---|
| **接** | 用户没说要存，只说「记一下」「这个留着」「我有个想法」，也能识别并落库 |
| **拆** | 一口气说五件事，拆成五条记录，各自归类，不混成一坨 |
| **归类** | 十个类型（想法/待办/事件/参考/决策/摘录/疑问/计划/复盘/定时）× 六个领域（工作/生活/学习/健康/财务/其他） |
| **编号** | 每条都有线索号 `Q20261105-01`；同一件事的后续补充沿用同一编号，形成演进时间线 |
| **提醒** | 由每小时运行的定时任务推送；支持任意提前量、循环规则（每周/每月/每年/农历/每 N 天），22:00–08:00 静默 |
| **执行** | 不止提醒：可以定时跑脚本、调 API、触发技能、多步组合，结果回写表里 |
| **回读** | 「我上次记的那个」「关于老张的那些」「最该先做哪个」，按字段筛，不靠全文搜 |
| **整理** | 把一周的碎片汇总成档案文档，正文用整理版，用户原话放文末附录 |

## 安装

复制整个目录到技能目录即可：

```bash
git clone https://github.com/<owner>/quicksave.git ~/.codebuddy/skills/quicksave
```

**首次运行不会自动建任何东西。** 技能会先跟你确认，你点头之后才建表、建定时任务、写配置凭证。装完会展示完整功能清单和使用示例。

## 依赖

这个技能**没有自己的脚本**，一个 `.py` 文件都没有。建表、写记录、查线索、建任务，全部调用 `library` 技能里已有的官方脚本。

```text
存储   library 技能 → space_api.py、database/*、doc/create_doc.py
调度   平台的定时任务能力（每小时一次）
执行   脚本 / HTTP API / 技能调用 / 组合
```

不复制脚本是刻意的：脚本随平台版本更新，副本一旦分叉，就会出现"照着旧逻辑调新接口"的静默错误。缺什么就调什么。

这也是它能换环境的原因——**不绑定具体平台**，只要目标环境能提供上面三类能力，改一处路径就能跑。详见 [`references/portability.md`](references/portability.md)。

## 数据长什么样

个人空间下一张表，21 个字段：

| 字段 | 类型 | 说明 |
|---|---|---|
| 内容 | text | 整理后的一句话，一眼认出是什么事 |
| 类型 | select | 想法 / 待办 / 事件 / 参考 / 决策 / 摘录 / 疑问 / 计划 / 复盘 / 定时 |
| 标签 | text | 只放主题词，2–4 个，`、` 分隔 |
| 线索 | text | 演进共用编号，如 `Q20261105-01` |
| 记录时间 | date | 记录当天 |
| 状态 | select | 待看 / 进行中 / 已完成 / 归档 |
| 到期 | date | 含时分；无明确时间留空 |
| 提醒 | select | 不提醒 / 准时 / 提前10分钟 / 1小时 / 1天 / 3天 / 1周 |
| 重复 | text | `每周一 09:00`、`每月5号`、`每年农历三月二十八`；空 = 一次性 |
| 下次触发 | date | 由程序维护，扫描时滚动更新 |
| 静音至 | date | 早于此刻不提醒。静音不是删除 |
| 完成于 | date | 勾完成时填，用于复盘耗时 |
| 执行 | select | 仅提醒 / 脚本 / API / 技能 / 组合 |
| 执行内容 | text | 命令原文或请求地址，不含凭据 |
| 任务ID | text | 执行类对应的独立定时任务 ID |
| 上次结果 | text | 由任务回写 |
| 领域 | select | 工作 / 生活 / 学习 / 健康 / 财务 / 其他 |
| 优先级 | select | 高 / 中 / 低，只给需要排先后的待办填 |
| 相关人 | text | 老张、妈、王总、李工；空 = 只跟自己有关 |
| 来源 | text | 链接、书名页码、谁在什么场合说的 |
| 原文 | text | **用户当时说的话，一字不改** |

字段顺序就是建表顺序，新增字段一律追加在末尾——插队会让老记录的列位置与文档对不上。

## 两个设计取舍

### 一、原文和内容分两个字段

一开始只有一个「内容」字段，要求它既"保留用户原话"又"一句话说清楚"，这两件事互斥，实际执行永远是整理赢：

```text
用户原话  那个周报啊，我是觉得每次都手动拼，太蠢了，能不能让它自己从聊天记录里长出来
内容      周报自动化：希望周报能从聊天记录自动生成，省掉每周手动拼装
原文      那个周报啊，我是觉得每次都手动拼，太蠢了，能不能让它自己从聊天记录里长出来
```

三个月后看到「内容」，你知道有这件事；看到「原文」，你才认得出是自己说的。所以拆成两个字段：内容给未来的自己看摘要，原文给未来的自己听声音。

规则只有一条硬的：**原文不进任何自动输出**——不推送、不进摘要、不合并。它只在「我原话怎么说的」和整理档案时被读。

### 二、文档里不写任何实例 ID

表被删掉重建过四次，每套 ID 都不同。写在文档里的那一刻就开始过期，照着过期值调用轻则 `permission denied`，重则写到别的表上还显示成功。

所以 `SKILL.md` 里**一行具体 ID 都不留**，只写取法：`spaceId` 从 `list-user-spaces` 取，`database_id` 从配置文档读，`folder_id` 按标题搜。唯一权威是 [`references/bootstrap.md`](references/bootstrap.md) 里那份会被真正执行的建表 JSON。

## 文件结构

```text
quicksave/
├── SKILL.md                主流程，零到十五章
├── CHANGELOG.md            版本变更，记录每次为什么改
└── references/
    ├── bootstrap.md        初始化：自检 + 建表 + 建任务 + 写凭证
    ├── first-run.md        怎么判断"是不是第一次"
    ├── config-doc.md       配置凭证模板
    ├── onboarding.md       装完给用户看的功能清单
    ├── reminder-prompt.md  定时任务执行指令
    ├── upgrade.md          升级与备份
    ├── portability.md      换环境怎么办
    ├── consistency.md      改完必跑的一致性检查
    └── dependencies.md     依赖与数据落点
```

`references/` 里的几份不要合并：初始化和升级是低频但高风险的动作，混进主流程会让日常记录也变重。

## 边界

- **不主动创建任何东西**，除非用户先确认
- **不管别人的内容**，只动自己产出的 `速记箱/`、`skills/`、`敏感配置/`
- **不猜**：拿不准就问一句，猜错比多问一句贵得多
- **不因为缺字段就不存**：来源不知道就留空，回头补
